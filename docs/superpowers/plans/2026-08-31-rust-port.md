# Rust Port Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the Python hook with a single static Rust binary, with byte-identical behaviour proven by differential testing rather than by hand-ported assertions.

**Architecture:** A `cargo` binary crate reading the same hook JSON on stdin and writing the same JSON on stdout. `src/higgsfield_lint.py` stays in the tree throughout as the **behavioural oracle**: a parity harness feeds identical inputs to both implementations and asserts identical output. The Python is deleted only after the Rust has run against real traffic.

**Tech Stack:** Rust (stable), `serde_json`, `regex`. Python 3 retained temporarily as the parity oracle.

**Spec:** `SPEC.md`, plus `src/higgsfield_lint.py` at commit `abd1238` as the executable specification.

**Predecessor:** `docs/superpowers/plans/2026-08-30-higgsfield-lint.md`, complete, 58 tests passing.

## Why the port

Recorded honestly, because the decision reversed twice. Rust was the original stack choice, justified on compile-time enforcement of three spec invariants. The pseudocode pass proved two of those three unbuildable as specified, and measurement then deleted the system they protected. The replacement was written in Python without consulting the person who chose the stack. That was the process error being corrected here.

What Rust buys the current shape is narrower and worth stating plainly, so nobody re-litigates it later:

- **A single binary with no runtime interpreter dependency.** Today the hook is `python3 "$CLAUDE_PROJECT_DIR/src/higgsfield_lint.py"`. If system Python moves or breaks, the hook exits 127, which `PreToolUse` treats as non-blocking, so it silently stops working and nothing says so.
- **The `rmcp` risk is gone.** That was the one genuine stack risk, and it belonged to the MCP proxy. A stdin-to-stdout binary needs no MCP SDK.
- Startup drops from roughly 40ms to about 1ms. That is 0.1% of a generation call and is **not** a reason to do this.

What it costs, equally plainly: two crate dependencies where Python needed none, a build step, and a new silent-failure mode (a stale or missing binary).

## Global Constraints

Carried verbatim from the predecessor plan, with Rust-specific mechanics named because the Python idiom does not translate:

- **Never block.** Never emit `permissionDecision: "deny"`.
- **Never exit non-zero, never write to stderr.** In Python this was one blanket `except Exception: pass`. **Rust panics write to stderr and exit 101**, which would violate both halves at once. The binary MUST install a silent panic hook and run its work inside `catch_unwind`, and the release profile MUST use `panic = "unwind"` (an `abort` profile makes the panic uncatchable). This is the single most important constraint in the port.
- **Fail silent.** Any malformed stdin, missing field, or internal error exits 0 with no stdout and no stderr.
- **No network, no filesystem writes.** The only read is `data/negative_prompt_models.json`.
- **Byte-identical output to the Python implementation** for every input the parity harness covers. Message wording, ordering, pluralisation, and the `request N:` prefix are all part of the contract.
- **Precision is the product, in both directions.** Unchanged.

## The translation hazards

These are the places a naive port silently diverges. Each has a task step that proves it did not.

| Hazard | Detail |
|---|---|
| **Lookaround is unsupported** | `_has_term` / `_find_original_case` use `(?<![a-z0-9])…(?![a-z0-9])`. The `regex` crate rejects lookaround outright. Reimplement as: find each case-insensitive occurrence of the literal, then inspect the preceding and following character and reject when either is ASCII alphanumeric. Do **not** reach for `fancy-regex` to dodge this; the manual scan is smaller and faster. |
| **Panic vs exception** | See Global Constraints. Python's blanket except has no free equivalent. |
| **Booleans are integers in Python** | `_is_int_dimension` exists solely because `isinstance(True, int)` is `True`. In `serde_json`, `Value::Bool` and `Value::Number` are distinct, so the hazard vanishes. **Keep the test anyway** — it documents intent and guards the JSON layer. |
| **Iteration order is contractual** | `CONFLICT_PHRASES` is a tuple, and `hits` preserves its order in the rendered message. Use a Rust array and iterate in order. Never a `HashSet`. |
| **`RESOLUTION_CLAIMS` order is not contractual** | `_claimed_short_side` selects by maximum pixels, so map iteration order is irrelevant. Safe to use any map. |
| **Regex features that DO port** | `\b`, `(?:…){0,2}`, and `re.IGNORECASE` as an inline `(?i)` flag are all supported. `NEGATION_RE` and `PLACEMENT_NEGATION_RE` translate directly. |
| **`json.dump` compactness** | Python's default separators produce `{"hookSpecificOutput": {...}}` with a space after each colon and comma. `serde_json::to_string` produces no spaces. The parity harness must compare **parsed JSON**, not raw bytes, or normalise both before comparing. |

|---|---|

`rust/tests/fail_silent.rs`:

```rust
use std::io::Write;
use std::process::{Command, Stdio};

fn run(input: &[u8]) -> (i32, Vec<u8>, Vec<u8>) {
    let exe = env!("CARGO_BIN_EXE_higgsfield-lint");
    let mut child = Command::new(exe)
        .stdin(Stdio::piped()).stdout(Stdio::piped()).stderr(Stdio::piped())
        .spawn().expect("spawn");
    child.stdin.as_mut().unwrap().write_all(input).ok();
    let out = child.wait_with_output().expect("wait");
    (out.status.code().unwrap_or(-1), out.stdout, out.stderr)
}

#[test]
fn every_pathological_input_exits_zero_and_silent() {
    let cases: Vec<Vec<u8>> = vec![
        b"".to_vec(),
        b"not json".to_vec(),
        b"{}".to_vec(),
        br#"{"tool_input": null}"#.to_vec(),
        br#"{"tool_input": "a string"}"#.to_vec(),
        br#"{"tool_input": {"params": "a bare string"}}"#.to_vec(),
        br#"{"tool_input": {"params": []}}"#.to_vec(),
        br#"{"tool_input": {"requests": "not a list"}}"#.to_vec(),
        br#"{"tool_input": {"requests": [null, 3, "x"]}}"#.to_vec(),
        vec![0xff, 0xfe, 0x00, 0x01],                       // invalid UTF-8
        format!(r#"{{"tool_input":{{"params":{{"prompt":"{}"}}}}}}"#, "a".repeat(5_000_000)).into_bytes(),
        format!("{}{}", "[".repeat(50_000), "]".repeat(50_000)).into_bytes(),
    ];
    for (i, case) in cases.iter().enumerate() {
        let (code, _out, err) = run(case);
        assert_eq!(code, 0, "case {i} exited {code}");
        assert!(err.is_empty(), "case {i} wrote to stderr: {:?}", String::from_utf8_lossy(&err));
    }
}

#[test]
fn an_internal_panic_is_still_silent_and_zero() {
    // Guarded by the panic hook plus catch_unwind, not by the absence of bugs.
    let (code, out, err) = run(br#"{"tool_input": {"params": {"__panic__": true}}}"#);
    assert_eq!(code, 0);
    assert!(err.is_empty());
    let _ = out;
}
```

- [ ] **Step 4: Implement `main.rs`**

```rust
use std::io::{Read, Write};
use std::panic;

mod lint;

fn run() -> Option<String> {
    let mut buf = Vec::new();
    std::io::stdin().read_to_end(&mut buf).ok()?;
    let text = String::from_utf8(buf).ok()?;            // invalid UTF-8 -> silence
    let payload: serde_json::Value = serde_json::from_str(&text).ok()?;
    let tool_input = payload.get("tool_input")?;
    let models = lint::load_models();
    let findings = lint::lint(tool_input, &models);
    if findings.is_empty() {
        return None;
    }
    let out = serde_json::json!({
        "hookSpecificOutput": {
            "hookEventName": "PreToolUse",
            "additionalContext": lint::render(&findings),
        }
    });
    serde_json::to_string(&out).ok()
}

fn main() {
    // SPEC 7: the hook must be invisible when it fails. A default panic hook would
    // print to stderr, which on PreToolUse is a blocking signal. Silence it first,
    // then swallow the unwind.
    panic::set_hook(Box::new(|_| {}));
    let result = panic::catch_unwind(run).unwrap_or(None);
    if let Some(text) = result {
        let _ = std::io::stdout().write_all(text.as_bytes());
    }
    std::process::exit(0);
}
```

fn has_term_respects_alphanumeric_boundaries() {
    // Must match
    for t in ["a 4K shot", "4K, cinematic", "shot in 4k.", "(4K)"] {
        assert!(has_term(t, "4k"), "should match: {t}");
    }
    // Must NOT match - alphanumeric on either side

**Files:**
- Create: `rust/tests/parity.rs`

**Interfaces:**
- Consumes: the finished binary and `src/higgsfield_lint.py`.

This is the task that makes the port trustworthy. Hand-ported assertions prove the Rust matches what the porter *believed* the Python did. A differential harness proves it matches what the Python *does*.

- [ ] **Step 1: Build the corpus**

Assemble inputs from three sources:

1. All four real fixtures in `tests/fixtures/`, each wrapped as `{"tool_name": "...", "tool_input": <fixture>}`.
2. Every pathological payload from `rust/tests/fail_silent.rs`.
3. A generated sweep: for each of the resolution lexicon terms, each `CONFLICT_PHRASES` entry, each negation form (`no X`, `without X`, `avoid X`, `not X`), the stopword idioms, the `without + gerund` shape, and dimension pairs `(16,9)`, `(64,64)`, `(1920,100)`, `(1376,768)`, `(true,true)` — compose a params object, with and without `negative_prompt`, with and without a known model. - [ ] **Step 2: Write the harness**

For each input, run the Rust binary and `python3 src/higgsfield_lint.py` with identical stdin. Assert:

- identical exit codes (both 0),
- both stderr empty,
- stdout either both empty, or both parse as JSON and compare **equal as parsed values** (not as raw bytes — Python and `serde_json` differ in separator whitespace, per the hazards table).

Report every divergence with the input that caused it. A single divergence fails the task.
